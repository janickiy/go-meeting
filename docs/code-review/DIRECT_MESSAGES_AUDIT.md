# Личные сообщения: аудит до реализации

Основа: коммит `2618053`, 6 октября 2026. Требование пользователя имеет приоритет над исходным промптом: отдельный пункт **«Личные»**, без раздела «Чаты» и вкладок. Чаты встреч остаются в конференциях.

1. **Пользователи.** `users`: UUID, email, password hash, nullable display_name, is_admin, guest_conference_id. Аватаров нет. Постоянная сессия хранится в PostgreSQL; JWT обновляется через HttpOnly cookie. Для личных сообщений нужны зарегистрированные аккаунты, без гостевого scope. Публичный DTO пользователя содержит email и поэтому не подходит для поиска собеседников.
2. **Существующая схема.** Миграция 13: `chat_messages`, `chat_attachments`, `chat_read_states` привязаны к conference_id. Есть sequence, уникальность ключа повторной отправки, индексы истории/непрочитанных, мягкое удаление и аренда загрузки.
3. **Модели.** `domain/chat` уже содержит Message, ReplyPreview, Attachment, ReadState, Page и общую нормализацию текста, UUID, файлов и отпечатка запроса. Их можно расширить идентификатором личной беседы, сохраняя поля конференций.
4. **REST.** `/conferences/:id/messages`, PATCH/DELETE сообщения, GET/PUT `/chat/read`, init/content/finalize/download вложений. Обработчик и usecase подходят для повторного использования. Репозиторий проверяет членство, активность встречи и роль модератора.
5. **События.** `chat.message.created/updated/deleted`, `chat.read.updated` используют conference envelope и conference hub. Их контракт сохраняется.
6. **Redis.** Уже есть одноразовые WS tickets и персональный NotificationBus с каналами пользователей. Присутствие участников конференции нельзя использовать как присутствие аккаунта.
7. **Frontend.** ChatPanel объединяет историю, reply/edit/delete, read cursor, composer и scroll. AttachmentUploader реализует повторяемую загрузку с прогрессом. Конференция обновляет React Query по своим WS events; Layout слушает уведомления через SSE.
8. **Повторное использование.** Общие domain/chat, usecase/chat, SQL-операции чата с адаптером таблиц/доступа, HTTP-handler, ChatPanel и AttachmentUploader. Отдельными будут только список бесед, поиск пользователей и транспорт аккаунта.
9. **Риск дублирования.** Копирование ChatRepository или ChatPanel создаст второй messenger. Вместо этого вводятся доверенные варианты scope/table и publisher/transport adapters. Проверки конференции сохраняются, личная беседа проверяет двух участников и права автора.
10. **Предлагаемая схема.** Новые `conversations` с канонической парой UUID и UNIQUE; `conversation_members` с курсором чтения; `conversation_messages` и `conversation_attachments` с прежними полями и ограничениями. Ограничения БД защищают состав пары и принадлежность reply/attachment/read. UUID пары исключают self messaging; гости исключаются при создании.
11. **Миграция.** Выбрана **B: compatibility adapter**. Conference storage и object prefixes остаются. Миграция 28 добавляет таблицы; данные, API и события прежнего чата не переезжают. Проверить применение на тестовой схеме со старыми сообщениями/вложениями/курсорами.
12. **Global WS.** `/api/v1/ws-ticket` → одноразовый ticket → `/api/v1/ws`. Проверяются Origin и постоянная сессия. Redis маршрутизирует события только двум участникам; очередь ограничена, writer один, disconnect освобождает подписку и присутствие. Отдельные Redis leases с TTL учитывают несколько вкладок и API. История PostgreSQL остаётся источником истины при потере Pub/Sub. Уведомления доступны в этом потоке; существующий SSE сохраняется для совместимости.
13. **Маршруты интерфейса.** `/personal` и `/personal/:id`. Desktop: список слева, переписка справа. Mobile: список → переписка → назад. Кнопка «Новое сообщение» открывает поиск по display_name. Пункт «Личные» показывает суммарное число непрочитанных. Email не отображается.
14. **Границы безопасности.** Account-only endpoints; членство на каждой операции; edit/delete только автору; reply/attachments только текущей беседы; signed URLs выдаёт сервер. Поиск минимум два символа, максимум 20 результатов и rate limit. Текст выводится как React text. JWT не передаётся в URL. Nginx должен защитить ticket в access/error logs и разрешить размер загрузки для нового scope.
15. **Пакеты.** `domain/chat`, новый `domain/conversations`-совместимый DTO личной беседы в отдельном пакете; PostgreSQL chat adapters и conversation projection; usecase publisher; personal REST/global WS; Redis user presence; API bootstrap; frontend API/transport/PersonalPage/global stream/Layout/routes/CSS; миграция, интеграционные тесты и документация.
16. **Порядок.** Схема и общий репозиторий → гонки pair/send/read и ограничения → publisher/REST/global WS/presence → общий UI и «Личные» → тесты безопасности/вложений/realtime/mobile → обязательные Go/race/vet/static/vuln/frontend gates и регрессии конференций/SFU/записи → итоговый отчёт. Без будущих typing/group/blocking функций.

Это описание решения до изменений кода, а не отчёт о готовой функциональности.
