# Meetrix: веб-интерфейс

Вёрстка по полному макету, токены, branding и новая структура экранов описаны в
[руководстве frontend](FRONTEND_GUIDE.md). Фактические проверки редизайна и
ограничения браузеров: [отчёт интеграции](FRONTEND_INTEGRATION_REPORT.md).

`frontend/` — React 19, TypeScript, Vite и React Query. Production-сборка раздаётся
Nginx и обращается к API через тот же origin. API контролирует доступ к встречам,
записям, материалам и административным данным; скрытие элемента интерфейса не
заменяет серверную проверку. Медиа проходит через отдельный `media-worker`, а
сборка записей — через recorder-worker.

## Маршруты и сценарии

| Путь | Что доступно |
| --- | --- |
| `/`, `/login`, `/register`, `/register/success` | Главная, вход, регистрация и результат регистрации |
| `/app`, `/meetings`, `/meetings/new` | Личный кабинет, список и создание встречи |
| `/meetings/:id`, `/meetings/:id/join` | Встреча и проверка устройств перед входом |
| `/i/:code` | Приглашение с переходом через регистрацию/вход |
| `/history`, `/history/:id` | Завершённые встречи и материалы разрешённого участника |
| `/calendar` | Предстоящее расписание: неделя/месяц и мобильный список |
| `/analytics` | Аналитика выбранной завершённой либо активной встречи |
| `/search`, `/notifications`, `/settings` | Поиск, уведомления и настройки |
| `/admin` | Сводка операций для учётной записи с `isAdmin` |

Старые адреса `/conferences`, `/conferences/new`, `/conferences/:id`,
`/conferences/:id/join`, `/app/recordings`, `/app/search`, `/app/settings`
остаются рабочими. OAuth callback календаря находится на
`/app/settings/calendar/:provider/callback` и обрабатывает одноразовый code/state.

Создание предлагает обычную или запланированную встречу, локальную дату и время,
плановую длительность и зал ожидания. После создания можно скопировать приглашение.
До входа участник видит название встречи, имя аккаунта, preview камеры, уровень
микрофона и выбор устройств, если браузер это поддерживает. Имя меняется в
настройках профиля; поле на экране проверки доступно только для чтения. Выбор
устройств хранится локально для этой учётной записи и проверяется при следующем
входе; `deviceId` не служит постоянной идентичностью. При исчезновении устройства
используется системное. Browser preview останавливается перед переходом в комнату.
Если включён зал ожидания, публикация медиа возможна только после серверного
допуска. В комнате доступ к камере и микрофону требует отдельного действия.

В комнате есть участники, чат и файлы, реакции, модерация,
субтитры, демонстрация экрана и запись с видимым статусом. Соединение показывает
статусы WebSocket/PeerConnection/ICE и даёт повторно подключиться. Блок
диагностики показывает RTT, долю потерянных входящих RTP-пакетов, входящий и
исходящий bitrate, тип выбранного маршрута (direct/relay), если браузер выдаёт
эти данные. Кнопка копирует обезличенный отчёт из разрешённых агрегатов без
SDP, IP, токенов и идентификаторов устройств. Это технический снимок, а не
оценка качества связи.
После переподключения аппаратный захват не включается сам. Права owner/co-host,
допуск и медиа-политика проверяются API и worker, а не только кнопками.

История открывает обзор, запись/плеер, расшифровку, итоги ИИ
и аналитику на отдельных вкладках. Чат открывается только в конференции. Тяжёлые панели отображаются по выбору вкладки;
доступ к материалам проверяется через membership. Поиск показывает только
разрешённые сервером материалы, с фильтрами и переходом к моменту записи.
Семантический и гибридный режимы предлагаются, только когда сервер сообщает об
их доступности. Итоги ИИ требуют человеческой проверки. Уведомления доступны
списком с отметкой прочтения и внутренними ссылками.

Настройки открываются модальным окном поверх текущей страницы, не меняя её URL.
Прямые `/app/settings` и `/settings` открывают то же окно над главной;
закрытие прямого адреса возвращает в `/app`. Доступны профиль, устройства,
уведомления и оформление, без пунктов интеграций и безопасности.
Светлая/тёмная тема и процентный размер текста сохраняются в `localStorage`
отдельно для каждого авторизованного аккаунта; публичные страницы и гостевой
вход используют светлое оформление и 100%. API, сессия и права от темы не зависят.
Настройки позволяют менять своё отображаемое имя, выбирать устройства,
предпочтения уведомлений, тему и размер текста. Подключение календаря через
окно аккаунта убрано; существующие серверные подключения и OAuth callback
не удалялись. Предпочтения устройств остаются в данном браузере. Внешние email,
push, STT, ИИ и embeddings по умолчанию выключены; режим `mock` не является
реальной доставкой или расшифровкой.

## Авторизация, возможности и административный доступ

- Google/Microsoft на форме входа временно отображаются как disabled-заглушки
  «Скоро». Реальный вход — email/password; календарный OAuth не используется для входа.
- JWT живёт один час и сохраняется в памяти и `sessionStorage` вкладки. Аккаунт
  остаётся авторизованным через серверную сессию и HttpOnly cookie; новый JWT
  получается автоматически до истечения старого и после открытия браузера.
  Временный отказ сети сохраняет профиль и открытый экран конференции.
  Logout очищает локальную сессию и кэш, отзывает серверную сессию и сохраняет
  отметку явного выхода для повторной попытки при восстановлении сети.
  Подробности: [постоянная авторизация](PERSISTENT_AUTH.md).
- `GET /api/v1/auth/me` восстанавливает публичный профиль. `PATCH /api/v1/auth/me`
  принимает только `{ "displayName": "Имя" }`; после обрезки внешних пробелов
  требуется 1–100 Unicode code points без управляющих символов. Ответ
  `200 {status,user}` обновляет профиль без смены JWT. Очистка имени не поддержана.
- `GET /api/v1/capabilities` требует JWT и сообщает безопасные флаги
  `liveCaptions`, `transcription`, `aiSummary`, `semanticSearch`,
  `meetingAnalytics`, поддержанные `recordingModes` и `buildVersion`. Адреса
  провайдеров, ключи и токены не возвращаются. Ответ управляет доступностью
  semantic/hybrid, captions, transcript/AI и analytics; неизвестный либо ошибочный
  ответ не разрешает функцию. Панели дополнительно учитывают серверные статусы и ошибки.
- `/admin` читает `GET /api/v1/admin/summary`: агрегаты активных встреч,
  подключённых участников, записей, заданий и отказов, readiness API/media-worker
  и состояние PostgreSQL/Redis/RabbitMQ/MinIO. Право `users.is_admin` задаётся
  оператором по проверенному UUID, отдельно от ролей конференции. API проверяет
  его на каждом запросе и отвечает `403` обычному пользователю. UI не показывает
  чат, расшифровки, секреты и персональные строки. Назначение права:
  [admin runbook](operations/admin.md).

Приложение отображает пользовательский текст как обычный React-текст, без
`dangerouslySetInnerHTML`. Production frontend отправляет CSP без `unsafe-eval` и
`unsafe-inline`, `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`.
При внешнем HTTPS `MINIO_PUBLIC_ENDPOINT` Nginx добавляет только его точный
origin к `img-src`/`media-src`; WSS origin берётся из явно заданного
`PUBLIC_FRONTEND_URL`, а не из заголовка Host. Не указывайте путь, query,
userinfo или wildcard в этих переменных: контейнер отклонит такой запуск.
В локальном HTTP-режиме для записей также допускается только точный loopback
origin MinIO (`localhost` или `127.0.0.1`); HTTPS-странице нужен HTTPS endpoint.
Подписанные ссылки на запись остаются краткоживущими bearer-ссылками: не помещайте
их в логи, аналитику или сторонние сообщения. JWT в `sessionStorage` не защищён
как HttpOnly cookie от XSS. API и WebSocket должны работать по HTTPS/WSS с
разрешённым origin; камера/микрофон в браузере требуют HTTPS или localhost.

## Запуск

Локальный Compose из корня проекта:

```sh
docker compose up -d --build media-worker api frontend https
```

UI: `http://localhost:5173` (loopback) или `https://localhost:18482` с
локальным сертификатом; прямой API: `http://localhost:8085`. Контейнер frontend
не получает корневой `.env` и серверные ключи. Nginx проксирует `/api/` к API,
а HTTPS proxy также обслуживает подписанные `/recordings/` ссылки. SPA deep links
возвращают `index.html`, не подменяя JSON-ошибки API. Для development:

```sh
cd frontend
npm ci
npm run dev
```

Нужен Node.js 22.22.2+, 24.15+ либо 26+; Docker-сборка использует Node 24.
Dev-сервер слушает `127.0.0.1:5173`, а `/api` проксирует на
`http://127.0.0.1:8085` (`API_PROXY_TARGET` меняет только dev proxy).
Production запуск и секреты описаны в [операционном runbook](operations/README.md).

## Версия артефакта и ошибки браузера

Каждая сборка включает публичный `/version.json` с тремя полями: `version`,
`commit`, `buildTime`. Эти же значения встраиваются в JavaScript; источник —
`VITE_BUILD_VERSION`, `VITE_BUILD_COMMIT`, `VITE_BUILD_TIME` при сборке.
В Docker им соответствуют аргументы `BUILD_VERSION`, `BUILD_COMMIT`, `BUILD_TIME`.
Для релиза передаются версия `vX.Y.Z`, SHA коммита и UTC-время вида
`2026-10-03T12:00:00Z`. Значения `dev`/`unknown` означают локальную сборку,
а не подтверждённый release. Серверные секреты и остальные переменные окружения
в JSON не включаются. Nginx запрещает использование сохранённого ответа без
повторной проверки. Этот адрес описывает frontend; версия API проверяется отдельно.

Телеметрия по умолчанию выключена. Для включения нужен frontend build argument
`CLIENT_TELEMETRY_ENABLED=true` (`VITE_CLIENT_TELEMETRY_ENABLED=true` при прямой
сборке) и серверный `CLIENT_TELEMETRY_ENABLED=true`. Смена frontend-флага требует
нового артефакта. Ошибки JavaScript, необработанные Promise и отказы рендера React
отправляются только на same-origin `POST /api/v1/client-errors`. React также
показывает экран восстановления с кнопкой обновления страницы.

Перед отправкой остаются только версия, шаблон маршрута, фиксированный код,
семейство браузера и максимум пять координат в JS-артефактах текущего origin.
Query, hash, UUID, код приглашения, исходное сообщение, имена функций, внешний
URL, содержимое чата/расшифровок, SDP, Authorization, cookies и Referer не
отправляются. Неизвестный путь превращается в `unknown`; подписанные URL и кадры
из исходных файлов разработки отбрасываются. Отправка ограничена пятью событиями
в минуту, двадцатью за страницу и подавлением одинаковых событий на десять секунд.
Адаптер не хранит очередь на диске, не повторяет неудачные запросы и не использует
сторонний SDK. Это ограниченная диагностика ошибок, а не аналитика действий.

Проверка версии и обезличивания транспорта в обоих браузерах:

```sh
VITE_CLIENT_TELEMETRY_ENABLED=true npx playwright test e2e/release-observability.spec.ts
```

## Проверки и ограничения

```sh
cd frontend
npm run typecheck
npm run lint
sh scripts/test-csp-config.sh
npm run test
npm run test:a11y
npm run build
npm run test:e2e
```

Vitest проверяет ключевые API/компонентные сценарии. Playwright из
`frontend/e2e/` в основном перехватывает API: прохождение таких тестов не
доказывает реальные PostgreSQL, SFU, TURN и запись. Опциональный
`TestFrontendPostgres` в `tests/integration` поднимает временную БД, реальные
handlers и Vite; его запускают только с явными test env, см. прежний сценарий в
исходнике теста. Отдельные Stage 3–8 браузерные и Docker-прогоны требуют
проверки с реальными сервисами. Для release используйте
[чеклист этапа 9](operations/RELEASE_CHECKLIST.md).

Реализованы skip link, навигация по вкладкам, focus trap для мобильного меню и
модалей, стили reduced motion и safe area. Эти меры не являются подтверждением
WCAG 2.1 AA. Ручной keyboard/screen reader аудит комнаты, реальные мобильные
устройства, Firefox/Safari и внешние WAN/TURN/TURNS сети остаются отдельными
release-проверками. В активной встрече доступны M/V/C; сочетания отключаются
при вводе текста и в диалогах. Полная локализация не введена:
основные пользовательские строки сейчас русские.

## Личные сообщения

Отдельная навигация «Личные»: `/personal` и `/personal/:id`.
`PersonalPage` содержит список/поиск собеседников, а история, composer,
reply/edit/delete и файлы используют общий `MessageThread` из `ChatPanel`.
`usePersonalRealtime` в Layout создаёт один account WS на вкладку для
зарегистрированного пользователя; этот канал не создаёт SFU/media session.
Список, badge и сообщения используют user-scoped query keys. Мобильный экран
адаптируется к VisualViewport и safe area. Чат встреч отсутствует во вкладках
истории и открывается только в комнате, включая чтение завершённой встречи.
Контракты и ограничения: [PERSONAL_MESSAGES.md](PERSONAL_MESSAGES.md).
