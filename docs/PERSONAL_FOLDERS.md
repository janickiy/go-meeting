# Папки личного пространства

## Назначение

Папки — личная организация доступных пользователю материалов. Отдельный пункт «Папки» находится в блоке «Личное пространство». В папку можно добавить личный чат, групповой чат и встречу. Встреча и её чат представляют один элемент с `conferences.id`. Записи и файлы не становятся элементами автоматически.

Папка не имеет сообщений, не создаёт новый чат и не предоставляет права доступа. Один элемент может находиться в нескольких папках. Удаление из папки удаляет только связь; удаление папки не удаляет разговоры, встречи или сообщения. Остальные участники не видят названия, порядок и состав чужих папок.

## Интерфейс

- `/folders`: список с доступными счётчиками; создание, переименование, удаление и изменение порядка кнопками вверх/вниз.
- `/folders/:id`: элементы, фильтры «Все», «Встречи», «Чаты», поиск и ограниченные страницы; добавление и удаление связей.
- «Добавить в папку» в меню личного/группового чата и карточки встречи: список папок с независимыми checkbox. Создание папки доступно в том же диалоге.
- Карточки переходят в существующий чат, встречу или историю завершённой встречи. В папке нет отдельного composer или медиасоединения.

Виртуальные фильтры «Все / Личные / Группы / Новые» в сообщениях остаются фильтрами. Они не хранятся в таблице папок. Управление папками и picker используют общие диалоги.

Название: 1–50 Unicode символов после trim и NFC; управляющие и bidi символы запрещены. У одного пользователя не допускаются совпадения после Unicode case-fold: «Работа» и «работа» — одно имя. Между пользователями имена независимы. Максимум 100 папок на аккаунт. Порядок папок сохраняется; внутри папки элементы сортируются по активности/дате, без ручного ранжирования.

## Схема и миграция

Миграция `000032_personal_folders`:

| Таблица | Поля и ограничения |
|---|---|
| `folders` | UUID, FK `user_id → users`, name/name_key, position, timestamps; unique owner/name_key и deferrable unique owner/position |
| `folder_conversations` | FK folder и conversation, created_at, составной PK |
| `folder_conferences` | FK folder и conference, created_at, составной PK |

Настоящие FK исключают несуществующие элементы и дубликаты связей. Каскад при удалении папки касается только её связей. Физическое удаление conversation/conference удаляет соответствующие ссылки. Обратные индексы target/folder поддерживают эти операции; owner/position/id поддерживает выдачу списка. Миграция добавляет таблицы и не переносит существующие сообщения. Down допускается только при отсутствии пользовательских папок; при наличии данных нужен совместимый forward fix.

## Доступ и жизненный цикл

Все операции требуют зарегистрированного аккаунта. Гостевые аккаунты не имеют папок. Чтение, изменение, удаление, reorder и picker ограничены владельцем. Неизвестная и чужая папка возвращают одинаковый `404`.

Разговор видим при текущем `conversation_members.left_at IS NULL`, допустимом типе direct/group и отсутствии `conversations.deleted_at`. Встреча видима при admitted/waiting membership, без kicked/rejected и явного выхода из conference chat. Обычный выход из звонка и приглашённый участник до подключения не равны потере доступа. Waiting получает только базовую карточку: без invite secrets, имён и числа участников. Число участников проецируется только при допущенном доступе к истории.

Проверка доступа находится в SQL до сортировки/LIMIT, проекции metadata и подсчётов. Сохранённая связь не заменяет membership. Потерявшие доступ элементы исключаются из папок, кандидатов, checkbox и счётчиков. Связь может сохраняться в БД и вновь стать видимой после восстановления доступа. Её можно удалить, даже если текущего доступа к элементу уже нет.

Добавление не вызывает join, приглашение, admission или изменение роли. Транзакция сначала проверяет owner-scoped папку, затем берёт SHARE lock целевого элемента и заново проверяет доступ, после чего блокирует папку и записывает связь. Изменение списка папок сериализуется по владельцу через `users FOR NO KEY UPDATE`, совместимый с FK key-share. Reorder принимает полный текущий набор принадлежащих пользователю ID; устаревший набор получает conflict.

## API

Префикс `/api/v1`; Bearer authentication, `Cache-Control: private, no-store`, `nosniff`, ограничение частоты. DTO папки: `id`, `name`, `position`, `createdAt`, `updatedAt`, `itemCount`, `conversationCount`, `conferenceCount`, опциональный `contains`.

| Метод | Путь | Данные |
|---|---|---|
| GET | `/folders` | Список до 100 папок; `itemKind` + `itemId` добавляют checkbox `contains` |
| POST | `/folders` | `{name}` → `{status,item}` |
| GET | `/folders/:id` | `{status,item}` с доступными счётчиками |
| PATCH | `/folders/:id` | `{name}` → `{status,item}` |
| DELETE | `/folders/:id` | Только папка и связи |
| PUT | `/folders/order` | `{ids:[...]}` → `{status,items}` |
| GET | `/folders/:id/items` | `type=all|conversation|conference`, `search`, `before`, `limit` |
| PUT / DELETE | `/folders/:id/items/:kind/:itemId` | Идемпотентная связь; kind conversation/conference |
| GET | `/folder-items` | Доступные кандидаты с теми же фильтрами и optional `folderId` → `inFolder` |

Страница элементов: `{items:[{type,item,inFolder?}],nextCursor?}`. Conversation использует существующий формат personal/group; Conference — базовую карточку без invite secrets. Размер страницы 1–100. Cursor связан с аккаунтом, областью, папкой, фильтром, поиском, датой, типом и UUID; между папками/аккаунтами/фильтрами его переносить нельзя. `search` — ограниченный literal substring, `%` и `_` не становятся SQL wildcard.

## Производительность и обновления

Counts и metadata получают доступные наборы общими SQL-проекциями без отдельных HTTP/SQL-запросов на каждую строку. Picker получает все папки и их checkbox одной выдачей; candidate/detail страницы ограничены keyset пагинацией. Repository делает 2 SQL-запроса для List/Get metadata и 4 для Items/Candidates с folderId; middleware зарегистрированного аккаунта добавляет ещё один. Число запросов не зависит от количества элементов на странице. Измерения и фактические PostgreSQL EXPLAIN приведены в итоговом отчёте аудита.

Общий user WebSocket доставляет только владельцу минимальные события `folder.created`, `folder.updated`, `folder.deleted`, `folder.items.updated` с `folderId` и `folder.reordered` с пустым payload. События публикуются после persistence и служат инвалидированию; REST остаётся источником данных. Другие участники conversation/conference не входят в получателей. Новое WS/media соединение не создаётся.

React Query keys включают user ID, requests отменяются через AbortSignal. При смене аккаунта диалоги и локальные данные прошлого пользователя сбрасываются. Собственное удаление из группы удаляет известные folder/candidate previews из cache. Отказ `403` при добавлении немедленно удаляет устаревший preview; authoritative `403/404` недоступной папки очищает её cache и закрывает диалог. Успешное удаление связи обновляет checkbox во всех загруженных страницах кандидатов и убирает карточку только из выбранной папки, даже если последующий refetch не удался. REST refetch при фокусе и каждые 15 секунд на видимой странице подтверждает доступ для внешних изменений встреч, которые не обязаны публиковать folder event.

## Границы этапа

Поддерживаются только direct, group и conference. Цвет, описание, закрепление, системные папки, drag/drop и отдельные записи/файлы не реализуются. Для будущих типов потребуется отдельная модель с настоящими FK и собственными правилами доступа. Публикация на production в этом этапе не выполняется.
