# Этап 9: чеклист выпуска Meet

Этот документ — список **условий выпуска**, а не отчёт об уже пройденной
production-приёмке. Отмечайте пункт только после прогона на конкретном build и
окружении; сохраните дату, commit/image digest, исполнителя и ссылку на результаты.
До этого локальные unit/build проверки не подтверждают браузеры, WAN, внешний TURN
или восстановление данных. Текущие экраны и API описаны в [frontend](../frontend.md),
административное право — в [admin runbook](admin.md), базовая эксплуатация — в
[операционном runbook](README.md).

| Поле релиза | Значение перед выпуском |
| --- | --- |
| Commit, image digests API/media/recorder/product/live/frontend/proxy | Заполнить |
| Окружение, публичный HTTPS origin, дата и ответственный | Заполнить |
| Версия схемы и время согласованного PG + MinIO backup | Заполнить |
| Результат browser/TURN/restore прогона | Заполнить ссылками на протоколы |
| Решение go/no-go и согласованный откат | Заполнить |

## 1. Проверка исходников и build

- [ ] Зафиксировать commit и digest каждого образа. Перед сборкой API задать
  `BUILD_VERSION` как неизменяемый release ID или сокращённый commit SHA и сверить
  встроенный `buildVersion` через авторизованный `GET /api/v1/capabilities`.
  Значение `dev` означает, что версия релиза не была передана при сборке.
- [ ] Выполнить `go test ./...`, `go test -race ./...`, `go vet ./...`,
  `govulncheck ./...` при наличии инструмента. Записать пропущенные opt-in тесты:
  обычный `go test ./...` не запускает интеграции без явных test env.
- [ ] В `frontend/` выполнить `npm ci`, `npm run lint`,
  `sh scripts/test-csp-config.sh`, `npm run typecheck`, `npm run test`,
  `npm run test:a11y`, `npm run build`, `npm audit --omit=dev`.
  `npm run lint` проверяет стиль через Prettier; проверка типов TypeScript —
  отдельный gate. GitLab CI также запускает style lint и проверку CSP origins.
- [ ] Запустить Playwright для критических маршрутов. Нынешние тесты
  `frontend/e2e/` в основном используют перехват API; дополнить их отдельным
  прогоном с реальными API/PostgreSQL, SFU, recorder и тестовыми STT/AI
  провайдерами. Сохранить trace/screenshots с очищенными персональными данными.
- [ ] Проверить регрессии этапов 3–8: WS/reconnect, SFU audio/video,
  демонстрацию экрана, TURN relay, зал ожидания и модерацию, чат/файл, запись
  и подписанные ссылки, расшифровку/ИИ/поиск, живые субтитры и аналитику.

## 2. Конфигурация, миграция и deployment

- [ ] До обновления ограничить новые записи/изменения, дождаться обработки
  активных записей и фоновых заданий. Создать **согласованный** backup
  PostgreSQL, MinIO objects/metadata и защищённую копию конфигурации/ключей.
  Проверить чтение backup и отдельный restore drill; измерить допустимые RPO/RTO.
- [ ] Сравнить `.env.production` с `.env.production.example`. Проверить
  независимые непустые JWT/media/internal/TURN/metrics/provider encryption keys,
  пароли, HTTPS origins, `WS_ALLOWED_ORIGINS`, `HTTP_TRUSTED_PROXIES`,
  `MINIO_PUBLIC_ENDPOINT`, `BUILD_VERSION`, certificate paths, `MEDIA_NAT_IPS`, public TURN IP,
  порты и доступность диска recorder. Не публиковать вывод env/Compose с секретами.
- [ ] Выполнить безопасную проверку конфигурации без вывода значений:

  ```sh
  docker compose --env-file .env.production -f docker-compose.production.yml config --quiet
  ```

- [ ] Проверить миграции на копии схемы с сопоставимым объёмом данных.
  `000021_admin_capability.up.sql` добавляет `users.is_admin BOOLEAN NOT NULL
  DEFAULT FALSE` и три обычных `CREATE INDEX`; регистрация не даёт это право.
  Индексы создаются в общей транзакции `RunMigrations` при старте API. На больших
  таблицах возможны задержка запуска и блокировки записей: измерить время на
  копии и согласовать окно обновления. Для `000021` нет down-скрипта: откат
  образа не должен автоматически удалять колонку/данные. Если более старый
  бинарник несовместим со схемой, использовать согласованный PG + MinIO snapshot.
- [ ] Для `000022_remove_raised_hands` подготовить backup и окно обслуживания.
  Остановить старый API перед удалением колонок, затем запустить новую версию.
  Down-скрипт возвращает структуру, но не исторические значения счётчиков;
  подробности и порядок отката — в [процессе релиза](../RELEASE_PROCESS.md).
- [ ] Развернуть из зафиксированных образов с контролем очередности зависимостей,
  API и фоновых worker. Production Compose пример:

  ```sh
  docker compose --env-file .env.production -f docker-compose.production.yml up -d --build
  ```

  Для реального релиза использовать сохранённые image digests и утверждённую
  процедуру deployment вместо непроверенного изменения исходников на сервере.
- [ ] Проверить `users.is_admin=false` у новых пользователей. Право назначать
  только по проверенному UUID в доверенной SQL-сессии с отдельным аудитом выдачи;
  owner/co-host конференции не получает глобальный доступ автоматически.

## 3. Флаги и безопасное включение функций

- [ ] Согласовать и записать значения `LIVE_STT_ENABLED`,
  `TRANSCRIPTION_ENABLED`, `AI_SUMMARY_ENABLED`, `EMBEDDINGS_ENABLED`,
  `MEETING_ANALYTICS_ENABLED` и режимы соответствующих провайдеров. Образец
  production держит эти функции выключенными; `noop` не выдавать за обработку,
  `mock` не применять как production провайдера.
- [ ] После старта под пользовательским JWT прочитать
  `GET /api/v1/capabilities`: флаги должны совпадать с реально включёнными
  службами, `semanticSearch` требует доступного pgvector. Ответ не должен
  содержать endpoint/token/secret. Проверить, что при выключенном semantic
  режиме поиск остаётся доступен по ключевым словам.
- [ ] Включать STT/AI/live/embeddings поэтапно на staging с тестовыми
  провайдерами и согласованным retention/стоимостью. Проверить состояния
  `queued/processing/ready/failed`, ограниченные повторы и деградацию при
  недоступности провайдера. Отключение флага — первая обратимая мера при сбое;
  уже поставленные задания и сохранённые результаты оценивать отдельно.
- [ ] Проверить доступные `recordingModes` и реальную композицию/аудиофайлы на
  целевых кодеках и ресурсных лимитах, а не только появление пункта в UI.

## 4. Readiness, безопасность и операционная сводка

- [ ] Проверить `/health/live` и `/health/ready` внутри доверенной сети для
  API, media-worker и recorder; отдельно проверить health product/live-worker,
  PostgreSQL, Redis, RabbitMQ, MinIO, свободный диск и отсутствие Rabbit backlog.
  Публичный production proxy должен закрывать `/health`, `/metrics`, `/internal`,
  `/debug`.
- [ ] Проверить HTTPS/WSS, сертификаты, same-origin API, CSP без
  `unsafe-eval`/`unsafe-inline`, `nosniff` и `Referrer-Policy: no-referrer`.
  Для внешнего HTTPS `MINIO_PUBLIC_ENDPOINT` убедиться, что в `img-src` и
  `media-src` добавлен только его точный origin; `connect-src` должен содержать
  только явно заданный WSS origin и не зависеть от заголовка Host.
  Убедиться, что access/error logs не сохраняют JWT, OAuth code/state, SDP,
  подписанные URL записи, тексты чата/расшифровок или provider secrets.
- [ ] Обычный JWT: `GET /api/v1/admin/summary` возвращает `403`; без JWT —
  `401`. Под явно назначенным admin JWT маршрут возвращает только агрегаты,
  readiness и ограниченные kind/code ошибок. После отзыва `is_admin` уже
  выданный JWT должен сразу получать `403`. Страница `/admin` также скрывает
  данные после серверного отказа; получение SPA HTML `200` само по себе не
  проверяет авторизацию.
- [ ] Проверить observability: `/metrics` только с отдельным Bearer secret,
  Prometheus/Grafana в закрытой сети, уведомление о сбое API/media/recorder,
  рост очереди и диска. Убедиться, что Alertmanager/доставка оповещений реально
  настроены; starter dashboard без доставки не закрывает этот gate.

## 5. Сквозная проверка пользовательского пути

- [ ] Зарегистрировать двух обычных пользователей, войти, проверить истечение
  JWT/logout, отсутствие раскрытия существования email и профиля/хеша в ответах.
- [ ] Создать немедленную и запланированную встречу, включить зал ожидания,
  скопировать приглашение. У второго пользователя проверить Pre-Join: preview,
  микрофон/камеру, уровень, выбор вывода при поддержке, запрет/отсутствие/смену
  устройства и fallback. После Join preview track должен остановиться.
- [ ] Проверить ожидание B, допуск A и отсутствие публикации медиа до допуска.
  Затем двусторонний звук/видео, mute/camera, screen share и native stop,
  moderation/отключение, реакции, чат и файл.
- [ ] При включённых функциях проверить субтитры и деградацию, запуск/остановку
  записи с видимым индикатором у обоих, обработку/готовый файл. Симулировать
  потерю WS/media-worker и проверить восстановление snapshot и явное повторное
  включение устройств.
- [ ] Завершить встречу: `/history/:id` — обзор, защищённое воспроизведение,
  переход к timestamp сегмента, расшифровка, итоги ИИ, чат и объективная
  аналитика; `/search` — keyword и, при разрешении сервера, semantic/hybrid.
  Неавторизованный/ожидающий/отклонённый участник не видит приватный текст.
- [ ] `/notifications` показывает счётчик, список и отметку прочтения;
  `/settings` сохраняет имя через `PATCH /api/v1/auth/me` (trim, 1–100 Unicode
  символов), после обновления имя видно без нового JWT, email/роль/пароль не
  меняются. Проверить локальные настройки устройств и календарь только при
  реально настроенной интеграции.

## 6. Браузеры, доступность, сеть и нагрузка

- [ ] Выполнить один и тот же короткий smoke отдельно в текущих Chrome,
  Edge и Firefox: вход, Pre-Join с доступом/отказом камеры, выбор устройств,
  двусторонний mic/camera, screen share/native stop, reconnect, запись и
  воспроизведение. Safari проверять отдельно на целевых версиях macOS/iOS и
  только после проверки совместимости Pion, `getUserMedia`, `setSinkId` и
  screen capture. Записать версии браузеров и недоступные browser API; успешный
  Chromium не считать результатом Firefox/Safari.
- [ ] Выполнить desktop и mobile portrait/landscape с реальными разрешениями
  камеры/микрофона, touch targets, safe areas, масштабом текста 200% и reduced
  motion. Проверить, что действия комнаты остаются видимыми без горизонтальной
  прокрутки. Текущие тесты Chromium с mock API не заменяют этот пункт.
- [ ] Пройти вручную **без мыши**: Tab/Shift+Tab от входа до создания встречи;
  открыть/закрыть модаль и мобильное меню клавишей Escape, проверить возврат
  фокуса; выбрать устройства и Join; в комнате добраться до mic/camera/screen,
  участников, допуска, чата, субтитров, записи и Leave; открыть историю и
  переключить вкладки Arrow/Home/End; проверить `/settings` и отказ `/admin`
  для обычного пользователя. Ни один dialog/menu не должен удерживать фокус
  после закрытия; активный элемент должен оставаться видимым.
- [ ] Повторить ключевые шаги с экранным диктором, проверить названия кнопок,
  состояние mute/recording/waiting, чтение ошибок и live captions без потока
  дублирующих объявлений. Прогнать axe и ручную проверку контраста. Текущий
  `npm run test:a11y` покрывает выборочные компоненты, не доказывает полное
  WCAG 2.1 AA.
- [ ] В двух реальных сетях проверить direct и принудительный TURN relay по
  UDP/TCP, затем TURNS с публичным сертификатом; проверить выбранную ICE пару,
  время жизни allocation, обновление credentials при новом PC, blocked UDP и
  reconnect. Локальные TURN тесты не подтверждают WAN/mobile/corporate network.
- [ ] Измерить загрузку production bundle, время отклика комнаты при чат/субтитрах,
  память/CPU/потерю пакетов на целевой численности участников и длительной
  записи. Сравнить с [baseline этапа 6](../CAPACITY_BASELINE.md), не переносить
  его локальные числа на production без измерения.

## 7. Откат и решение о выпуске

- [ ] Перед выпуском сохранить прежние image digests, конфигурацию, схему и
  процедуру возврата трафика. Проверить совместимость старых бинарников с
  миграцией `000021` на копии БД. Down migration с удалением колонки не запускать.
- [ ] При сбое сначала остановить включение затронутого feature flag, drain
  текущую нагрузку, сохранить диагностические данные без приватного содержимого.
  Для отката образов следовать [runbook](README.md#backup-restore-и-rollback):
  остановить новую версию, поднять закреплённые прежние образы и проверить
  readiness, регистрацию, вход, существующую встречу и запись.
- [ ] Если схема или данные несовместимы, восстановить согласованный
  PostgreSQL + MinIO snapshot. Явно зафиксировать возможную потерю изменений
  после snapshot; Redis presence/leases не восстанавливать как durable данные.
- [ ] Решение **go** допускается после фактического выполнения обязательных
  пунктов на целевом окружении или явного принятия оставшихся рисков владельцем
  выпуска. До отдельной проверки помечать как **не подтверждено**: production
  deployment, внешний WAN/TURNS, Firefox/Safari/mobile matrix, полный keyboard
  и screen reader путь, восстановление backup, реальная доставка оповещений,
  длительная запись и production capacity.
